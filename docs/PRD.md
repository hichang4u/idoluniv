## 01. 제품 개요
*Product Overview*

> **Executive Summary**
> IdolUniv는 K-pop을 중심으로 한 글로벌 아이돌 팬덤 커뮤니티 플랫폼입니다. 단순 게시판을 넘어 팬들이 직접 콘텐츠를 생산·소비·유통하며 아이돌과 실질적으로 연결되는 **슈퍼앱(Super App)** 형태의 차세대 팬덤 생태계를 지향합니다.

| 항목 | 내용 |
|---|---|
| 🎤 제품명 | IdolUniv (아이돌유니브) |
| 🏢 운영 주체 | 1인 운영 → 커뮤니티 자치 구조로 점진 전환 |
| 🌍 서비스 범위 | MVP 한국어 → 2단계부터 글로벌 (한/영/일/중/태) |
| 🖥️ 플랫폼 | Web (Mobile First) + PWA(2단계) |
| ☁️ 인프라 | Vercel (Frontend) + Supabase (Backend) |
| 📅 MVP 목표 | 클로즈드 베타 2026-11 (추정) · 공개 베타는 베타 결과로 결정 |

### 문제 정의 (Problem Statement)

| 😤 현재 팬들의 불편함 | ✅ IdolUniv의 해결책 | 해결 단계 |
|---|---|---|
| Weverse, Bubble, X, Instagram에 분산된 팬 활동 | 그룹별 게시판 + 실시간 라운지를 한곳에 | 1단계 |
| 언어 장벽으로 인한 글로벌 팬덤 소통 어려움 | AI 기반 다국어 번역 | 2단계 |
| 팬덤 기여도 인정 시스템 없음 | 팬덤 레벨 시스템 & 배지 | 2단계 |
| 컴백·콘서트 일정 통합 관리 부재 | 통합 팬 캘린더 | 2단계 |
| 팬 창작물 수익화 채널 부재 | 팬 마켓 + 후원 + 펀딩 생태계 | 3단계 |

### MVP 목표 (Goals)

1. **그룹별로 모이는 장소를 연다.** 팬이 자기 그룹 게시판에서 글·댓글을 쓰고, 같은 그룹 팬과 실시간으로 대화한다.
2. **1인 운영자가 감당할 수 있는 자정 수단을 갖춘다.** 신고 → 숨김이 관리자 화면에서 완결된다.
3. **사용자 단위로 행동을 식별한다.** 제재·rate limit·카운트 무결성이 가능한 식별 체계를 쓴다 (D-1 = A, 쓰기 전부 로그인 필수 — 2026-09-29 결정).
4. **재방문 여부를 측정할 수 있다.** 베타 기간 중 [14 KPI](#14-kpi--측정)의 선행 지표를 읽을 수 있어야 한다.

### MVP 비목표 (Non-goals)

MVP 에서 **하지 않는다**. 요청이 와도 2단계 이후로 넘긴다.

- 이미지·영상 업로드 (글 유형 `image`/`video` 는 폼에서 숨김)
- Markdown 렌더링 (평문 + 줄바꿈만)
- 다국어 UI, AI 번역
- 팬덤 레벨·포인트 (`fan_profiles.level/exp/points` 컬럼은 있으나 갱신 로직 없음 — 그대로 둔다)
- 그룹 팔로우, 개인화 홈 피드
- 광고, 결제, 멤버십
- 네이티브 앱, 푸시 알림
- 제재(경고·정지) 자동화 — MVP 는 콘텐츠 숨김까지

## 02. 시장 분석
*Market Analysis*

> 이 절의 수치는 v1.0 에서 옮긴 것이며 출처가 기재되어 있지 않다. 투자·제휴 자료로 쓰기 전에 출처를 붙여야 한다. ❓

| 트렌드 | 현황 | 시장 기회 | 전략 |
|---|---|---|---|
| **K-pop 글로벌 시장** | 2024년 약 $12B 규모 (출처 필요) | 다국어 팬덤 허브 부재 | 글로벌 올인원 허브 선점 |
| **팬 플랫폼 분산** | Weverse, Bubble, X, Instagram 파편화 | 통합 올인원 플랫폼 수요 | 슈퍼앱 형태 통합 |
| **AI 콘텐츠 생산** | 팬픽, 이미지, 번역 AI 수요 급증 | AI 기반 팬 활동 지원 | Claude + Replicate 통합 |
| **크리에이터 이코노미** | 팬이 곧 크리에이터인 시대 | 팬 창작물 수익화 생태계 | 팬 마켓 + 수수료 모델 |
| **Z세대 커뮤니티** | 숏폼·실시간·참여형 선호 | 인터랙티브 팬덤 경험 | 숏폼 피드 + 투표 |

### 경쟁사 분석

| 플랫폼 | 강점 | 약점 | IdolUniv 차별점 |
|---|---|---|---|
| **Weverse** | 공식 아이돌 연동, 글로벌 MAU | 소속사 의존, 팬 창작 제한 | 팬 주도 생태계 + AI 도구 |
| **Bubble** | 아이돌 DM 서비스 | 일방향 소통, 고가 구독 | 팬↔팬 양방향 커뮤니티 |
| **Twitter/X** | 실시간성, 글로벌 reach | 알고리즘 불안정, 팬덤 기능 부재 | 아이돌 특화 게시판 + 구조화 |
| **DC인사이드** | 국내 팬덤 문화 장악 | 레거시 UI, 글로벌 미지원 | 모던 UX + 다국어 + 모바일 |

### MVP 포지셔닝

MVP 는 기능 수로 위 플랫폼과 경쟁할 수 없다. 1단계의 차별점은 하나로 좁힌다.

> **"우리 그룹 팬만 모인, 깨끗하게 관리되는 모바일 게시판 + 라운지"**

- 대비 대상은 Weverse·Bubble 이 아니라 **DC인사이드 갤러리·X 해시태그** 다 (그룹별 공간이지만 관리·모바일 UX 가 약한 곳).
- 따라서 1단계 성공 조건은 기능 추가가 아니라 **콘텐츠 품질(신고율·처리 시간)과 모바일 사용성** 이다.

*Vision & Mission*

> **Vision** — "모든 팬이 자신의 아이돌 유니버스를 직접 설계하는 세상"

### 🛡️ 보안

- **모든 권한은 DB 에서 강제** — RLS(행) + 컬럼 GRANT(열) + security definer 함수(카운터·관리 작업). Server Action 의 조건문은 방어선으로 치지 않는다 ✅ (`0004` 원칙)
- security definer 함수는 `search_path` 고정, 필요한 역할에만 `EXECUTE` 부여 (0008 이후 anon 실행 가능 함수는 `get_or_create_chat_room`·`record_post_view` 뿐이어야 함 — 대시보드 S22 확인 대기 ❓, BACKLOG P0-4)
- 클라이언트가 넘긴 식별자(`session_id` 등)를 신원 증명으로 쓰지 않는다
- Rate limiting: MVP 는 채팅·글·댓글·신고 쓰기에 사용자 단위 적용 🟡 — 구현됨 (0009 글·댓글, 0010 채팅, 0011 신고) ✅. API 전반은 2단계
- 세션: Supabase Auth 기본(짧은 access token + refresh token). v1.0 의 "JWT 7일 만료" 는 삭제 — 로그인 유지 기간은 필요 시 별도 정의

- OWASP Top 10 대응, 특히 XSS: 사용자 콘텐츠는 평문 렌더. Markdown 도입 시 sanitize 필수

### 12.2 MVP 에 추가한 스키마 (구현됨)

09-24 판의 초안은 0007~0011 로 구현됐다 ✅. 상세 DDL 은 마이그레이션 파일과 TECH-DESIGN §3·§4 가 원본이다. 초안과 달라진 점만 적는다.

#### `reports` (0011)

|---|---|
| `target_author_id` | 신고 시점 작성자 (2단계 제재용) |
| `snapshot` (jsonb) | 신고 시점 내용. 원문이 지워져도 검토 가능 (AD-9) |

RLS: 신고자는 본인 신고 select 만, 관리자는 전체 select. **insert·update 는 RPC 전용** (`submit_report`, 관리자 RPC) — 초안의 "신고자 insert" 와 다르다.

#### 관리자 판별 — D-3: `admins` 테이블 (0007)

| 안 | 내용 |
|---|---|
| `users.role` 컬럼 | 기각. `users` 에 UPDATE 권한이 생기면 실수로 열릴 위험 |
| `admins` 테이블 | **채택·구현**. 정책 없음 = 클라이언트 접근 불가, 판별은 `private.is_admin()`. 첫 관리자는 SQL 에디터로 지정 (README) |

#### `moderation_actions` (감사 로그, 0011)

`id`, `actor_id`(null = 시스템 자동 숨김), `action` (`hide` \| `unhide` \| `auto_hide` \| `dismiss`), `target_type`, `target_id`, `note`, `created_at`. insert 는 RPC 에서만, 관리자만 조회. 초안과 차이: `auto_hide` 추가, **`report_id` 컬럼 없음** (대상 단위로 기록).

## 16. 리스크 관리
*Risk Management*

### 🔴 HIGH — 권한 우회로 인한 데이터 변조 🆕
브라우저가 anon key 로 PostgREST 를 직접 부를 수 있으므로, DB 권한이 하나라도 열려 있으면 앱 검사를 우회해 데이터를 바꿀 수 있다.
**완화:** 0004~0011 원격 적용, D-1 = A 로 RPC 재작성(0008), CI pgTAP(TECH-DESIGN §9.2), 권한 변경마다 `qa-reviewer` 검토 — 완료 ✅ (2026-10-11). 남은 것: 대시보드 S22·권한 표 확인(BACKLOG P0-4), Supabase 기본 권한 강제 전환(2026-10-30, R2) 직후 회귀 확인(BACKLOG P0-5).

### 🔴 HIGH — 저작권·초상권 분쟁: 팬 창작물 내 아이돌 이미지 사용
**완화:** 명확한 저작권 정책 고지, 권리자 신고 경로([6.4](#64-권리자-신고-저작권초상권)), 상업적 사용 구분 가이드라인. MVP 는 업로드가 없어 노출이 작다.

### 🔴 HIGH — 1인 운영 한계: 트래픽 급증·악성 콘텐츠 대응 불가
**완화:** 신고 누적 자동 임시 숨김(F7-5), 처리 목표 시간 명시, 커뮤니티 모더레이터 조기 구성(2단계), Vercel/Supabase 자동 스케일.

### 🔴 HIGH — 미성년자 보호 🆕
핵심 페르소나에 17세 사용자가 있고, 실존 인물 대상 성적 콘텐츠·합성물은 형사 처벌 대상이 될 수 있다 ❓.
**완화:** 만 14세 미만 가입 차단(L-1), 실존 인물 성적 팬픽 금지(6.1), `sexual` 신고 12시간 처리, 증거 보존.

### 🟠 MEDIUM — 일정 지연 🆕
원 8주 계획이 8주 이상 밀렸고, 1인 개발이다.
**완화:** MVP 범위 축소(01 비목표), 단계 종료를 날짜 대신 조건으로 정의(15), 결정 대기 항목(18)을 명시해 병목을 드러낸다.

**완화:** 팬 주도 생태계 차별화, 관리 품질로 포지셔닝(02), 소속사 직접 의존도 최소화.

### 🟢 LOW — Supabase / Vercel 서비스 장애 · 요금제 한도
