Sprint 개요 Overview

목표 — PRD 1단계(Foundation) 기능 전체를 8주 안에 완성하여 2026 Q2 베타 출시. 각 Sprint는 독립적으로 배포 가능한 단위로 설계되어 있어 중간 점검·피드백이 용이합니다.
Sprint 기간 핵심 목표 주요 기술 상태
Sprint 1 Week 1–2 Foundation Setup — 프로젝트 초기화 + 인증 Next.js 16 · Supabase Auth · shadcn/ui 코드 완료 · 외부 미확인

Sprint 3 Week 5–6 Realtime & Media — 채팅 + 업로드 + 반응형 Supabase Realtime · Storage · Tailwind 부분 착수
Sprint 4 Week 7–8 Admin & Launch — 관리자 + SEO + 배포 Vercel · GitHub Actions · Sentry 미착수

상태 열: 2026-09-24 코드·git 이력 기준으로 갱신 (원안은 Sprint 1 "진행 중", 나머지 "대기"). 주요 기술의 "Next.js" 는 실제 설치 버전(next@16.2.6)에 맞춰 "Next.js 16" 으로 정정. 실사용 여부: React Query·Zustand 는 package.json 에만 있고 코드에서 import 하지 않음.

03

운영 원칙 Sprint Rules

🔁 Sprint 기본 원칙

  • • 각 Sprint = 2주 / 14일
  • • Sprint 종료 시 Vercel 배포 가능 상태 유지
  • • 미완 태스크는 다음 Sprint로 이월 (스코프 조정)
  • • PR 단위 개발 → Vercel Preview 검증 후 merge
  • • 커밋 컨벤션: feat / fix / chore / docs

🎯 1인 개발 최적화

  • • 엄격한 deadline 대신 체크포인트 개념으로 운영
  • • 완성도 > 기능 수 — 덜 만들고 잘 만들기
  • • UI는 shadcn/ui 컴포넌트 우선 활용
  • • DB 변경은 Supabase Migration으로 추적
  • • 에러 핸들링은 Sprint 4에서 일괄 보강
스코프 원칙 — 각 Sprint의 태스크는 "Must Have"와 "Nice to Have"로 분리합니다. Must Have가 완료되면 Sprint를 닫고, Nice to Have는 다음 Sprint 백로그에 추가합니다.
