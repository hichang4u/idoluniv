## 0. 요약

1. **지금 디자인은 "방향"이라기보다 shadcn 다크 테마에 보라 그라데이션 로고를 얹은 상태다.** 목업 annotation 도 "기존 컴포넌트 수치를 옮겼다"고 적고 있어, 브랜드를 의도해 설계한 결과로 보기 어렵다 ○. 팬덤 서비스라는 인상을 주는 요소는 그라데이션 로고와 진행 바 두 곳뿐이다.
2. **그룹(아이돌)의 정체성이 화면에 없다.** 모든 그룹이 똑같은 보라 그라데이션 타일에 이니셜 한 글자로 표시된다 ✅. 팬덤 서비스의 핵심 단위가 시각적으로 구분되지 않는다.
3. **보라 + 핫핑크 조합은 BTS(보라)·TWICE(Neon Magenta)를 동시에 연상시킬 위험**이 있다 ○. 그룹을 가로지르는 서비스의 브랜드 색으로는 부적합하다(§4.3).
4. **관습과 반대다.** 확인한 한국 팬 커뮤니티(더쿠·인스티즈·Weverse 웹)는 모두 라이트 기본이고, Weverse·Berriz 는 Pretendard 를 쓴다 ✅(§4).
5. **한글 타이포그래피가 설계되지 않았다.** 한글 웹폰트가 없어 OS마다 글꼴이 다르다(Windows 는 맑은 고딕, iOS 는 Apple SD Gothic Neo). 라틴 글꼴 Geist 와 섞여 굵기·자간이 어긋나고, 어절 중간에서 줄이 바뀐다 ✅(렌더).
6. **다크 표면 단계가 사실상 하나다.** 배경 대 카드 명암비 1.05, 카드 대 muted 1.08 ✅. 카드 경계는 8% 흰 선이 전부다.
7. **색 역할이 겹친다.** 좋아요에 쓰려던 accent 핑크(`#fd2e80`)와 삭제·오류 destructive(`#f9423d`)가 같은 "뜨거운 빨강" 계열이다 ✅(OKLab 거리 0.095). primary 보라는 sRGB 색역 밖이라 모니터마다 다르게 보인다 ✅.
8. MVP 에 필요한 화면은 21개, 별도 디자인이 필요한 상태까지 **약 33개**(어림 수)다. 목업은 4장뿐이고, 그중 2장(홈 피드, 프로필 게이미피케이션)은 MVP 범위 밖 기능을 전제로 그려졌다 ✅ — §6.

**권장 방향**: §5 **A. 중립 캔버스 + 그룹 색**(라이트 기준·시스템 따름, Pretendard, 브랜드 색 최소화, 그룹 공간에만 그룹 hue) + 팬픽 상세에만 읽기 모드. IA 는 **그룹 중심**(§6.2 B).

> 2026-09-29 갱신: A 로 결정. 팬픽 뷰어는 **Pretendard 기본 + 명조(리디바탕) 선택**으로 바뀌었다(첫 권장은 명조 기본). 확정 명세는 `TOKENS.md`.

**권장 진행 순서**: 브랜드 방향 결정(🔷 D-15, §5) → 타이포·색 스페시멘 → 토큰 재설계 → 핵심 6화면 고해상도 목업 → 구현. 기능 구현(TECH-DESIGN T4~)은 **토큰·컴포넌트 규칙이 정해진 뒤** UI 를 붙이는 순서로 조정하기를 권한다.

## 3. 현재 비주얼 방향 진단

### 3.1 지금 방향이 전달하는 인상 ○

| 요소 | 현재 | 읽히는 인상 |
|---|---|---|
| 배경 | 거의 검정 남색 `#020409` | 개발자 도구·AI 서비스·암호화폐 대시보드의 흔한 다크 테마 |
| 색 | 전기 보라 + 핫핑크 그라데이션 | "Z세대·네온" 상투 조합. 2020년대 초 SaaS 랜딩에서 흔하다 |
| 글꼴 | Geist(Vercel) | 개발자 제품의 인상. 한글과의 짝이 설계되지 않았다 |
| 형태 | shadcn 기본 반경·테두리 카드 | 어느 shadcn 앱과도 구분되지 않는다 |
| 이미지 | 없음 | 아이돌·팬덤 서비스인지 화면만 봐서는 알기 어렵다 |

### 3.2 원점에서 다시 봐야 하는 이유

1. **차별점이 화면에 없다.** PRD 의 포지셔닝(팬이 운영하는, 그룹을 가로지르는, 글·팬픽 중심 커뮤니티)이 디자인 결정으로 번역되지 않았다.
2. **그룹 정체성 체계가 없다.** 팬은 "내 그룹 공간"에 들어왔다고 느껴야 한다. 지금은 모든 그룹 공간이 같은 보라다.
3. **보라·핑크가 특정 팬덤 색으로 읽힐 위험.** K-pop 에서는 여러 팬덤이 공식 색을 갖는다. 서비스 전체 브랜드 색이 한 팬덤의 상징색과 겹치면 "그 그룹 팬 사이트"로 보이거나 다른 팬덤의 거부감을 살 수 있다 — 구체 대조는 §4 (조사 결과 반영).
4. **다크 기본의 근거가 약하다.** PRD 는 "다크 기본"을 원칙으로 적었지만 이유를 적지 않았다. 글을 오래 읽는 커뮤니티(팬픽 포함)에서 다크 기본이 맞는지는 따로 판단할 문제다 — §4.

### 4.2 팬이 "원래 그렇다"고 느끼는 관습

1. **그룹 단위 공간으로 들어간다.** 즐겨찾기로 고정(Weverse), 그룹별 게시판 목록(더쿠·인스티즈). → IA-B(§6.2)를 뒷받침한다.
2. **인기글 모음(HOT)** 이 있다.
3. **게시판 단위 익명이 강한 관습**이다(더쿠·인스티즈). IdolUniv 는 계정 닉네임으로 활동한다(D-1=A) — 참여 문턱이 될 수 있다. 제품 결정이지 디자인 결정은 아니므로 🔷 D-21 로 올린다.
4. **텍스트 리스트형 고밀도 목록**이 팬 운영 커뮤니티의 표준이다 ○. 카드형은 공식 플랫폼 쪽에 가깝다.
5. **"⋯" 메뉴에서 신고**, 규칙을 공개적으로 명시한다.

## 5. 브랜드 방향 후보

세 방향 모두 §4.3·§4.4 의 제약(중립 브랜드 색, 공식 자산 미사용, 그룹 색은 그룹 공간에서만)을 지킨다. 차이는 **무엇을 서비스의 얼굴로 삼느냐**다.

| | A. 중립 캔버스 + 그룹 색 ○ 권장 | B. 팬진 (에디토리얼) | C. 나이트 스테이지 (현 방향 정제) |
|---|---|---|---|
| 한 줄 | 흰 종이 같은 중립 화면에, 들어간 그룹의 색이 입혀진다 | 팬이 만든 잡지. 글과 팬픽이 주인공 | 공연장 조명 아래 응원봉. 실시간이 주인공 |
| 기본 테마 | 라이트 기준 설계 + 시스템 따름(다크 지원) | 따뜻한 오프화이트(종이) + 다크 지원 | 다크 기본 |
| 브랜드 색 | 잉크(거의 검정 남색) 1색 + 아주 작은 시그니처 포인트 | 잉크 + 종이색. 포인트 색 거의 없음 | 중립 다크 표면 + 그룹 색이 "빛"으로 번짐 |
| 그룹 표현 | 그룹 헤더·탭 밑줄·버튼에 그룹 hue | 표지 띠·섹션 머리 색 | 채팅·헤더에 그룹 hue 글로우 |
| 타이포 | Pretendard 하나, 위계는 굵기·크기로 | 제목·팬픽 본문에 명조, UI 는 Pretendard | Pretendard, 굵은 제목 |
| 목록 밀도 | 텍스트 리스트 기본 + 이미지 글만 썸네일 | 여백 넉넉한 읽기 목록 | 카드형 |
| 맞는 기능 | 게시판·채팅·관리자 모두 무난 | 게시판·팬픽 매우 강함, 채팅 약함 | 채팅·라이브 강함, 긴 글 약함 |
| 관습 적합 (§4.2) | 높음 (라이트·리스트·Pretendard) | 중간 | 낮음 (다크 강제, 카드) |
| 차별성 | 중간 — 그룹 색 테마가 차별점 | 높음 | 낮음 (다크 네온은 흔함) |
| 위험 | 밋밋해질 수 있음 → 그룹 색·타이포 완성도에 의존 | 명조 웹폰트 용량, 채팅과 결이 다름 | 읽기 피로, "게임·공식 앱" 인상, 현재의 문제(표면 단계·색역) 재발 |
| 구현 비용 | 낮음 (shadcn 토큰 체계에 그대로 얹힘) | 중간 (읽기 컴포넌트·두 번째 글꼴) | 낮음 |

**권장: A 를 기본으로 하고, 팬픽 상세 화면에만 B 의 읽기 모드를 가져온다** ○.

근거:
1. 크로스팬덤 서비스의 얼굴은 중립이어야 한다(§4.3). A 는 브랜드 색을 최소화하는 대신 그룹 색이 그 자리를 채운다.
2. 공식 사진을 쓰지 못하는 제약(§4.4) 아래에서 그룹 정체성을 만드는 가장 싼 수단이 색이다.
3. 한국 팬 커뮤니티의 관습(라이트, 텍스트 리스트, Pretendard)에 맞아 첫 방문의 낯섦이 적다(§4.2).
4. 팬픽 읽기는 조사한 서비스 어디에도 없는 공백이라(§4.5) B 의 장점만 국소적으로 쓰면 차별점이 된다.

이 판단은 스크린샷 비교 없이 내린 것이다. **결정 전에 세 방향의 스페시멘(같은 게시판 화면을 세 가지로)을 렌더해 비교**하기를 권한다(§10-2).

### 7.3 재설계 구조 제안 ○

토큰을 3층으로 나눈다. 값은 §5 방향이 정해진 뒤 채운다.

```
원시 (primitive)      gray-0…12, brand-1…12, 상태색 스케일, group-hue 목록
      ↓
시맨틱 (semantic)     surface-0/1/2/3, text-strong/default/subtle/disabled,
                      border-subtle/strong, action-primary/-hover/-pressed,
                      like, scrap, danger, success, warning, info, focus-ring
      ↓
컴포넌트 / 컨텍스트   group-accent (그룹 공간에서만 덮어씀), post-type-{text,fanfic,image,video}
```

- **`like` 와 `danger` 를 분리**한다(§7.2 문제). 하트는 브랜드 감정색, 삭제·오류는 경고색으로 다른 계열에 둔다.
- **그룹 색 체계**: 그룹마다 `hue` 하나만 저장(`idol_groups.accent_hue` 🔷 — DB 변경이 필요하므로 TECH-DESIGN 과 동기화)하고, 명도·채도는 시스템이 정한다. 그러면 어떤 그룹 색이 들어와도 대비 기준을 지킨다. 공식 팬덤 색을 그대로 쓰지 않는 이유(상표·공식 사칭 오해)는 §4 조사로 보강한다.
- **표면 단계**: 다크에서 테두리 대신 명도 차(단계당 명암비 1.15 이상 목표 ○)로 층을 만든다.
- **색역**: 모든 원시 색을 sRGB 안에 둔다(OKLCH chroma 상한 확인). P3 강화는 나중 일.

## 8. 접근성

지난 리뷰 §1.4·§4 의 미달 항목은 토큰 재설계로 한꺼번에 해소한다. 새 토큰의 **수용 기준**:

- 본문 텍스트 4.5:1, 큰 텍스트(18.66px bold / 24px) 3:1, 입력창 경계·포커스 링 등 비텍스트 3:1 (WCAG 2.1 AA)
- primary 버튼 글자는 어떤 그룹 색이 들어와도 4.5:1 — 그룹 색은 hue 만 받고 명도는 시스템이 고정하는 이유
- 색만으로 상태를 전달하지 않는다(좋아요 = 채운 하트 + 숫자, 활성 탭 = 색 + 굵기/아이콘 채움)
- 터치 영역 44px, 입력 글자 16px
- `prefers-reduced-motion` 존중
