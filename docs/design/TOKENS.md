## 1. 원칙

1. **브랜드 고유색이 없다.** 서비스의 얼굴은 잉크(거의 검정)와 중립 회색이다. 색은 "지금 들어와 있는 그룹"만 가진다. 특정 팬덤의 상징색으로 읽힐 위험을 피하기 위해서다(DESIGN-ANALYSIS §4.3).
2. **그룹 공간 밖에서 `primary` = 잉크.** 그룹 공간(`data-group-color` 가 붙은 영역) 안에서만 `primary` 가 그룹 파스텔로 바뀌고 `primary-foreground` 는 잉크가 된다. 버튼 바탕은 `bg-primary text-primary-foreground` 만 쓰면 된다.
   - **주의**: 그룹 안에서 `primary` 는 파스텔이므로 **`text-primary`·`border-primary`·`ring-primary` 를 글자·표시에 쓰지 않는다**(흰 바탕 대비 1.2~2.6). 글자·표시는 `text-group-text` / `border-group-text`.
3. **모든 값은 sRGB 안에 있고, 대비를 계산으로 검증했다.** OKLCH 로 적되, 브라우저가 색역 밖 색을 임의로 보정해 명도가 바뀌는 일이 없게 채도를 미리 깎았다 ✅.
4. **색만으로 상태를 전달하지 않는다.** 좋아요는 채운 하트 + 숫자, 오류는 아이콘 + 문장, 활성 탭은 굵기 + 밑줄.

## 2. 층 구조

```
원시값 (gen.py 안의 L·C·h)
  └─ IdolUniv 토큰  --iu-surface-0 … --iu-group-solid        ← 디자인이 말하는 이름
        └─ shadcn 이름  --background, --primary, --muted …    ← components/ui 가 쓰는 이름 (매핑만)
```

- 제품 코드(`app/`, `components/` 중 `ui/` 제외)는 **Tailwind 의 shadcn 이름**(`bg-card`, `text-muted-foreground`, `bg-primary`)을 계속 쓴다. 새 역할(그룹 soft 면 등)만 `--iu-*` 를 Tailwind 테마에 추가해 쓴다(§8).
- shadcn 의 `accent` 는 **메뉴·ghost 버튼의 hover 면**이다. 지금 코드는 이것을 브랜드 핑크로 써 왔다(`from-primary to-accent` 그라데이션 4곳) — 이관 대상(§9).

### 3.2 그룹 색 — 파스텔 팔레트 24색

**방식**: 관리자가 그룹마다 **이름 붙은 파스텔 24색 중 하나**(`color_key`)를 고른다. 2026-09-29 개정(§11) — 첫 안의 "15° 간격 색상각 + 같은 명도·채도 공식"은 기계적인 무지개로 보여(사용자 피드백 "너무 AI 같다") 버렸다.

- **색마다 따로 조율했다.** 노랑·라임은 더 밝고 선명하게, 파랑 계열은 조금 깊게, 먼지 낀 색(세이지·모브)과 중립색(그레이지)도 넣었다. 색상 간격도 고르지 않다(분홍·파랑 계열이 촘촘).
- **파스텔 위 글자는 항상 잉크다.** 흰 글자는 파스텔 위에서 대비가 나오지 않는다. 잉크 글자 대비는 24색 모두 6.86 이상 ✅.
- **표시(indicator)는 진한 톤(`group-text`)이 맡는다.** 파스텔은 흰 바탕과의 대비가 1.2~2.6 이라 탭 밑줄·하트·진행 바·선택 테두리처럼 "상태를 알려 주는 선·아이콘"(비텍스트 3:1)에 쓸 수 없다 ✅.
- 모든 값은 sRGB 안에 있고 브라우저 색역 보정이 일어나지 않게 채도를 미리 깎았다.

역할(그룹 공간 안에서):

| 토큰 | 라이트 | 다크 | 쓰는 곳 |
|---|---|---|---|
| `--iu-group-solid` | 파스텔 (L 0.76~0.945) | 파스텔 (라이트보다 L −0.02) | 주 버튼(글쓰기·전송·다음 화) 바탕, 그룹 타일, 선택된 칩 바탕 |
| `--iu-group-on-solid` | 잉크 | `surface-0` | solid 위의 글자·아이콘 — **항상 이것만** |
| `--iu-group-text` | 진한 톤 (L 0.44) | 파스텔 톤 (L 0.86) | 유형 라벨, 연재 표시, **활성 탭 밑줄·채운 하트·진행 바·선택 테두리** |
| `--iu-group-soft` | 아주 옅은 톤 (L 0.965) | 어두운 톤 (L 0.30) | 그룹 헤더 띠 |
| `--iu-group-soft-strong` | 옅은 톤 (L 0.925) | L 0.36 | soft 위 눌림·강조 |

**금지**: `group-text`(진한 톤)를 `group-solid`(파스텔) 위 글자로 쓰지 않는다 — 코랄·세이지·틸·코발트·라일락·모브 6색에서 4.5 미만이다 ✅. 파스텔 위는 잉크.

**알려진 한계** ○

- 파스텔 버튼은 흰 바탕 위에서 경계가 약하다(비텍스트 대비 1.2~2.6). 버튼은 잉크 글자로 식별되므로 WCAG 상 허용되지만, 흰 목록 위에 파스텔 버튼 하나만 떠 있으면 흐려 보일 수 있다 → 주 버튼은 그룹 헤더 띠(soft) 위나 하단 고정 바에 둔다.
- 로즈·코랄 그룹은 채운 하트(진한 톤)가 `danger` 와 비슷하게 보인다. 하트는 모양으로, 오류는 아이콘 + 문장으로 구분한다.
- 팬덤 공식색을 그대로 옮기려는 용도가 아니다. 가까운 파스텔을 고르는 **구분용**이며, 관리자 가이드에 적는다.

| 뷰어 선택: 명조 | **리디바탕 (RIDIBatang)** | `"AppleMyungjo", "Batang", serif` | SIL OFL 1.1 ✅([눈누](https://noonnu.cc/en/font_page/324)). 전자책 본문용으로 설계됨. 굵기는 Regular 하나로 알고 있음 ○ → 명조 모드에서도 제목은 Pretendard |
| 뷰어 선택: 다른 고딕 | 나눔스퀘어 (선택 사항) | Pretendard 로 폴백 | SIL OFL 1.1 ✅([라이선스](https://github.com/blood72/NanumSquare/blob/master/LICENSE)). Pretendard 와 인상이 달라 선택지로 의미가 있다. Spoqa Han Sans Neo 는 Pretendard 와 비슷해 선택지로서 차이가 작다 ○ (D-24 결정) |
| 숫자 | Pretendard + `tabular-nums` | — | 조회·좋아요·댓글 수 |

**글꼴 스택** (Pretendard 공식 권장 형태):

```css
font-family: "Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, Roboto,
  "Helvetica Neue", "Segoe UI", "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif;
```

뷰어 전용 글꼴(리디바탕·나눔스퀘어)은 **사용자가 그 글꼴을 고를 때만** 내려받는다. 기본 번들에 넣지 않는다(첫 화면 용량 보호).

**로딩 방식** ○: Pretendard 의 **dynamic subset**(글자 범위별로 나눈 woff2 를 `unicode-range` 로 필요한 것만 받는 방식)을 쓴다. 가변 글꼴 한 파일은 한글 전체를 담아 수 MB 라서 모바일 첫 화면(LCP)에 불리하다. 구현 후보는 두 가지다 — (a) `pretendard` npm 패키지의 dynamic subset CSS 를 전역 CSS 로 import, (b) woff2 를 `public/` 에 두고 `@font-face` 직접 작성. `next/font/local` 은 가변 글꼴을 지원하지만(Next 16 문서 `font.md` ✅) 수십 개 서브셋의 `unicode-range` 를 다루는 방법은 문서에서 확인하지 못했다 ❓ → 구현 시 1회 검증.

### 4.2 크기 스케일 (모바일 기준)

| 토큰 | 크기 / 행간 / 굵기 | 쓰는 곳 |
|---|---|---|
| `title-1` | 24 / 1.35 / 700 | 팬픽 작품 제목, 빈 상태 제목 |
| `title-2` | 20 / 1.4 / 700 | 게시글 상세 제목, 시트·온보딩 제목 |
| `title-3` | 17 / 1.4 / 700 | 그룹 이름(헤더 띠) |
| `screen` | 16 / 1.4 / 600 | 상단 바 화면 제목 |
| `body-lg` | 16 / **1.75** / 400 | 게시글 본문, 입력창(iOS 확대 방지 16px) |
| `body` | 15 / **1.7** / 400 | 댓글, 채팅 메시지 |
| `list-title` | 15 / 1.45 / 600 | 목록 제목 (2줄 말줄임이라 행간을 좁힌다) |
| `label` | 14 / 1.4 / 500 · 활성 600 | 버튼, 탭, 칩 |
| `meta` | 13 / 1.5 / 400 | 작성자·시간·지표 |
| `caption` | 12 / 1.45 / 500 | 유형 라벨, 배지, 보조 안내 |

| `reading` | 16 / **1.8** / 400, 자간 −0.005em, 색 `text` | 팬픽 뷰어 본문 기본(Pretendard). 줄 길이 약 28~32자 ○ |
| `reading-serif` | 17 / 1.8 / 400, 자간 0 ○, 색 `text` | 뷰어에서 명조를 고른 경우. 명조는 같은 크기에서 작아 보여 1px 키운다 ○ |

- **굵기 위계**: 제목·작품 제목 600~700, 본문 400, 보조 강조 500. **800 이상은 쓰지 않는다**(2026-09-29 개정 — 첫 안의 800·900 을 낮춤). 위계는 굵기보다 크기·색(`text-strong` 대 `text-subtle`) 차이로 먼저 만든다.
- 자간: 제목 −0.02em, UI·본문 **−0.01em**(`body` 기본값으로 전역 지정), 뷰어 본문 −0.005em, 숫자 0 ○(렌더 확인 필요).
- **행간은 전부 단위 없는 비율**로 적는다(`1.8`, `1.75`). 뷰어에서 사용자가 글자 크기를 바꿔도 행간이 같이 비례한다. `px`·`rem` 행간 금지.
- 뷰어 본문 색은 `text-strong` 이 아니라 **`text`**(라이트 `#2f3339`, 다크 `#dee0e3`)다. 순흑·순백에 가까운 글자는 긴 글에서 눈이 부시다. 대비는 라이트 12.68, 다크 12.06(surface-1) ✅.
- 줄바꿈: 전역 `word-break: keep-all`, 본문·댓글·채팅에 `overflow-wrap: anywhere`(긴 URL). DESIGN-ANALYSIS R-2 해소.
- 목록 제목은 2줄까지(`line-clamp-2`), 상단 바 제목은 1줄 말줄임.
